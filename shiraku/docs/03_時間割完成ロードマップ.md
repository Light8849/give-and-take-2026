# 時間割完成ロードマップ（準備 → 完成 → 運用）

本校（週6日制・中高一貫・41クラス・教員108名）の規模を前提にした、年度時間割完成までの道のりと手順。
師楽での作業フェーズに対応させてある。日付は一般的な私立中高のモデル（本校の実日程に合わせて調整すること）。

## 全体像

```
Phase 0  操作習得（師楽高等学校＝ソフトの機能棚卸し）  …… いつでも / 今
Phase 1  条件の棚卸し（紙上・Excel上）                …… 12月〜1月
Phase 2  マスタ入力（教員・教科・クラス・教室）        …… 1月〜2月
Phase 3  コマ（授業）登録と条件入力                    …… 2月
Phase 4  骨格固定（合併・展開・非常勤・会議）          …… 2月下旬〜3月
Phase 5  自動配置 → 手直しの反復                      …… 3月
Phase 6  機械検証・関係者校閲・確定                    …… 3月下旬
Phase 7  年度内運用（授業変更 = Give&Take、次年度への記録） …… 通年
```

---

## Phase 0: 師楽（高等学校版）の操作習得・機能棚卸し

**目的**: 本校データを触る前に、師楽の「思想」を掴む。
※「師楽高等学校」はソフト製品名（YE DIGITAL製・高校版・12学年対応）。
デモ版や同梱サンプルデータがあればそれを練習台にする。詳細は `docs/02`。

- [ ] 画面構成（ウィザード／マスタ／先生別・クラス別コマ設定／条件／配置盤面）を一巡する
- [ ] 「時間割作成モード5つ」の各モードの内容を確認してメモする
- [ ] 練習データで**自動作成を最後まで実行**してみる（何分かかるか、何が「残る」か観察）
- [ ] わざと矛盾する条件（同じ教員の全時限禁止など）を入れて、**エラー時の挙動**を確認
- [ ] 手動でコマを動かすときの操作と、**「確定」（ロック）機能**の使い方を確認
- [ ] **CSV/Excelの入出力メニューの有無を確認**（Web上に情報なし。最重要確認事項） → 結果を `docs/02` に反映
- [ ] 条件設定画面にある項目を全部書き出す（＝師楽で表現できる条件の一覧になる）
- [ ] 保存の仕様を確認（**自動保存なしの模様**。版番号付きのこまめな手動保存を習慣化）

**成果物**: 「師楽でできること・できないこと」メモ（スクショを Claude に渡せば資料化します）

## Phase 1: 条件の棚卸し（最重要・紙上で行う）

**目的**: 自動配置失敗の原因の大半は矛盾条件。入力前に紙上で潰す。

- [ ] `docs/04_条件洗い出しチェックリスト.md` を教務内で回覧・記入
- [ ] 教育課程表（各クラスの科目×単位数）を確定させる
- [ ] 非常勤の契約（出勤可能曜日・時限）を確定させる ← **ここが遅れると全部遅れる**
- [ ] 常勤の研究日・分掌・会議体の曜日時限を確定させる
- [ ] 合併・展開授業の設計（どのクラス束で・何展開・担当は誰か）を確定させる
- [ ] 特別教室（体育館・理科室・音楽室・PC室等）の同時使用上限を確認する
- [ ] 条件を「**絶対条件**」と「**努力条件**」に仕分ける

**チェックポイント（Claudeに検証依頼できる）**:
教科ごとに「必要コマ数 ≦ 担当者の供給可能コマ数」か。
例: ある曜日に研究日が集中している教科は、その曜日の必要コマ数を賄えるか。

## Phase 2: マスタ入力

- [ ] 教員マスタ（108名: 氏名・教科・常勤/非常勤・担任）
- [ ] クラスマスタ（41クラス: 中学4×3、高校9/10/10、コース属性）
- [ ] 時程マスタ（月〜金8限＋土3限。**中高の昼休み時差**をどう表現するか要設計）
- [ ] 教室マスタ（特別教室・体育施設）
- [ ] 入力後、一覧をエクスポート（または画面スクショ）して Claude に渡す → 転記ミス検査

## Phase 3: コマ登録と条件入力

- [ ] 教育課程表どおりに各クラスの授業コマを登録（合併・展開は束で定義）
- [ ] 教員の出勤不可・禁止時限を入力（94名分の研究日、107名分の禁止時限）
- [ ] 会議・分掌ブロック（105名分）を入力
- [ ] 「1日の最大コマ数」「連続コマ上限」等のポリシー条件を設定
- [ ] **登録コマ数の突合**: クラス週コマ数の合計 = 登録コマ総数か（エクスポートして機械検証）

## Phase 4: 骨格固定（自動配置の前にやる）

置く順番の原則 = **自由度が低いものから**:

1. 土曜プログラム（27クラス合同・担当4名）等の全校固定枠
2. 合併・展開ブロック（拡大選択A/B、総合的な探究、合同体育、第2外国語）
3. 非常勤の授業（出勤日が動かせない）
4. 体育（施設制約）・芸術等の特別教室科目
5. 会議・分掌枠のロック

- [ ] ここまでを「ロック（固定）」して自動配置の対象から外す

## Phase 5: 自動配置 → 手直しの反復

- [ ] 自動配置を実行。**残ったコマ（配置不能）のリストを必ず記録**（スクショ→Claudeへ）
- [ ] 残りコマの原因分析: どの条件がボトルネックか（Claudeが分析を手伝う）
- [ ] 対処の優先順: ①努力条件を緩める → ②担当の入れ替え → ③絶対条件の再交渉
- [ ] **版番号を付けて保存**（前年度は23版。各版で「何を変えたか」を1行メモ）
- [ ] 版ごとにエクスポート → `analyzer.html` で機械検証

## Phase 6: 検証・校閲・確定

- [ ] `analyzer.html` フルチェック: 二重配置・出勤不可違反・禁止時限違反・会議重複・
      昼休み消失（中4限×高5限）・連続5コマ以上・日7コマ以上
- [ ] 教科主任校閲（教科内の並び・実習の連続性など機械で見えない質の確認）
- [ ] 非常勤本人への確認（契約と実配置の突合）
- [ ] 担任のLHR・学年会の整合
- [ ] 印刷物・配布データの作成

## Phase 7: 年度内運用と「来年度への貯金」

- [ ] 日々の授業変更は Give&Take ツールで運用（本リポジトリの index.html）
- [ ] **変更が頻発する箇所を記録** → それは来年度の時間割で条件化すべき箇所
- [ ] 年度末に「今年の反省 → 来年の初期条件リスト」を Claude と一緒に整理
